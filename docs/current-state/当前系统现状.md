# 当前系统现状

> 说明：本文件只记录已验证事实，不记录 Timescale 迁移计划或未实现目标。

## 1. 当前真实链路

- Collector 数据写入与聚合链路已收敛到单一事实层：`public.realtime_quotes -> public.kline_minute -> public.kline_daily`。
- 当前盘中运行标准：
  - 主源为 `sina`
  - 采集 cadence 为 `2s`
  - 正常连续采集窗口为 `09:29:56-11:30:03`、`12:59:58-15:00:03`
  - `sina` 写入必须携带 source-side timestamp
  - collector 依赖 `(instrument_id, quote_time)` 主键和 source-side timestamp CHECK 约束丢弃重复快照
  - 秒级写库使用 `ON CONFLICT (instrument_id, quote_time) DO NOTHING`，不再对重复快照做大表查重或更新
  - 非交易时段不写 heartbeat；交易时段 heartbeat 当前按 `2s` 节流
- 当前这三张事实表均已完成 Timescale hypertable 迁移：
  - `public.realtime_quotes`，chunk interval = `1 day`
  - `public.kline_minute`，chunk interval = `30 days`
  - `public.kline_daily`，chunk interval = `365 days`
- `public.daily_basic` 已落表并完成 Timescale hypertable 初始化：
  - 时间列为 `trade_date`
  - 当前已完成 `2020-01-02` 到 `2026-04-08` 的 `daily_basic` 历史同步
- 当前 TimescaleDB 版本为 `2.26.1`。
- `kline_daily` 采用影子表迁移完成切换；原影子回退表 `public.kline_daily_pre_timescale_20260407` 已于 `2026-04-08` 清理。
- 当前数据库不存在 `bar_3s / bar_1m / bar_30m / kline_second / v_bar_5m / v_bar_15m / v_bar_60m` 这些过渡对象。
- collector 目录现已补齐最小脚本实现：`collect_realtime.py`、`run_realtime_loop.py`、`reconcile_daily.py`、`source_probe.py`。
- 当前盘中链路实现已拆分为两条常驻进程：
  - `run_realtime_loop.py`：只负责秒级写入 `public.realtime_quotes`
  - `run_minute_aggregation_loop.py`：独立从 `public.realtime_quotes` 聚合 `public.kline_minute`

## 2. 当前运行方式

- 作业层（`collect_realtime` / `reconcile_daily`）在 `job_runs` 有记录，反映采集与日线重建触发与执行状态。
- 数据质量异常通过 `data_quality_log` 记录，例如 `daily_reconcile/source_error`（AKShare 请求失败）。
- `kline_minute` 的增量聚合口径与 `period` 结构已稳定存在，覆盖 `1/5/15/30/60`。
- `kline_daily` 当前库内不再保留影子回退表；历史日线已于 `2026-04-08` 从远端库 `192.168.10.50:7007/stock` 回灌恢复。
- `daily_basic` 当前由独立脚本 `collector/sync_daily_basic.py` 同步；`Tushare daily_basic` 指标不再继续写回 `kline_daily`。
- `realtime_quotes` 与 `kline_minute` 已于 `2026-04-08` 清理 `2026-04-07` 以前的盘中历史，只保留 `2026-04-07` 起的数据窗口。
- 当前盘后任务清单已拆分：
  - `16:30`：`reconcile_daily(当日) -> sync_daily_basic(当日)`
  - `20:00`：`sync_eastmoney_sectors -> sync_eastmoney_sector_stocks`

## 3. 当前数据库事实

- 三张主事实表均已成为 Timescale hypertable，当前行数核验通过。
- `daily_basic` 已成为 Timescale hypertable；当前已写入 `7,379,935` 行，范围为 `2020-01-02` 到 `2026-04-08`。
- `kline_minute` 覆盖 period：`1/5/15/30/60`，全部 `source` 当前值为 `derived`。
- `realtime_quotes` 当前以 `sina` 为主源；`sina` 行必须带 source-side timestamp。
- `kline_daily` 当前历史范围为 `2010-01-28` 到 `2026-04-08`。
- `daily_basic` 当前字段最小集为：`turnover_rate / total_share / float_share / free_share / total_market_cap / circulating_market_cap / source / version / updated_at`。
- `public.pool_members_current` 已完成股票池归属口径迁移：
  - `pool_id` 继续表示当前最深主池
  - `membership_mask` 表示全部股票池归属位掩码
  - 当前本地库已落 `membership_mask bigint`
- `kline_minute` 的 `15/30/60` 分钟分桶已修正为交易时段对齐：
  - 上午以 `09:30` 为起点
  - 下午以 `13:00` 为起点
  - `2026-04-10` 已重建验证，不再出现 `09:15 / 09:00 / 08:30` 异常桶
- `realtime_quotes` 与 `kline_minute` 当前行数会随盘中采集持续变化；当前保留窗口以 `2026-04-07` 起的数据为准。
- `kline_daily` 的新日线保留窗口目标已收敛为 `>= 2020-01-01`，但在 `bs` 完成实际裁剪并核验前，当前事实仍以上述历史范围为准。
- 板块当前主线只保留：
  - `public.standard_sectors`
  - `public.standard_sector_stocks`
  - `public.job_runs`
  - `public.data_quality_log`
- 旧板块表 `public.sector_mapping`、`public.sector_operation_log`、`public.sector_quotes_daily`、`public.sector_sync_log`、`public.sectors` 已删除，不再属于当前库事实。

## 4. 当前 collector / backend / frontend 现状

- collector
  - 当前已具备最小可执行脚本，负责实时采集、循环调度、源探测与盘后校准。
  - 运行态 failover state 由 `collector/runtime/source_failover_state.json` 记录，循环采集仅对真实源故障做退避/切换，并支持备源探测后自动回主源。
  - 以 `realtime_quotes -> kline_minute -> kline_daily` 作为 collector 主模型边界。
  - 东方财富板块目录与成分股同步已收敛到 `standard_sectors` / `standard_sector_stocks`，并通过 `job_runs` / `data_quality_log` 追踪运行状态。
- backend
  - 按规范不直接访问第三方，仅读本地数据库。
  - 股票池接口已按 `pool_id + membership_mask` 口径工作，`pool_id` 作为主池，`membership_mask` 作为全部归属标签。
- frontend
  - 已迁移为 Vue 3 + Vite + Element Plus + Pinia + Vue Router 的正式工程。
  - 当前已落地首阶段页面：Dashboard / 股票池工作台 / 个股详情 / 交易计划中心。
  - 页面布局和一级、二级菜单以 [前端开发与页面落地V1.5.md](/Users/wt/work/stockx/docs/design/前端开发与页面落地V1.5.md) 和 [交易系统设计V1.5.2.md](/Users/wt/work/stockx/docs/design/交易系统设计V1.5.2.md) 为当前开发文档入口推进；旧版前端文档仅作为历史补充，视觉基线参考 `pure-admin-thin`。
  - 当前前端通过本地 backend 的 REST 接口和 WebSocket 端点获取真值，不再以旧静态原型作为主入口。
  - 前端仍只做展示和交互，不在前端重算核心交易信号。

## 5. 当前未解决问题

- 采集运行组件已在仓库中落为最小脚本，但仍缺少进程守护、调度编排与部署封装。
- `kline_minute` 生成存在幂等性与窗口边界风险（聚合函数使用增量叠加策略），需下一步收敛。
- `reconcile_daily` 的失败告警集中在外部源错误，需明确重试与退避策略。
- `standard_sector_stocks` 的成员同步已经有独立 collector 命令，但东财源抓取仍会受外部接口稳定性影响，需依赖退避与质量日志观测。
- `kline_daily` 的新保留窗口计划收敛为 `>= 2020-01-01`；待 `bs` 执行完成后，再把 current-state 改写为完成事实。
