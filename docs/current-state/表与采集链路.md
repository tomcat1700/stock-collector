# 表与采集链路

## 1. 核心表

- `public.realtime_quotes`
  - 盘中事实表（秒级快照），已是 Timescale hypertable。
  - chunk interval：`1 day`
  - 用于盘中聚合前置与监控基线。
- `public.kline_minute`
  - 统一分钟层，已是 Timescale hypertable。
  - `period` 区分 `1/5/15/30/60`。
  - chunk interval：`30 days`
- `public.kline_daily`
  - 盘后日线真值层，已是 Timescale hypertable。
  - 历史只增不删，不允许破坏历史事实。
  - chunk interval：`365 days`
  - 采用影子表迁移完成切换；原回退影子表已于 `2026-04-08` 清理。
- `public.daily_basic`
  - 日度基础指标层，已是 Timescale hypertable。
  - 与 `public.kline_daily` 按 `(instrument_id, trade_date)` 对齐。
  - chunk interval：`365 days`
- `public.job_runs`
  - 作业执行审计与重试状态记录。
- `public.data_quality_log`
  - 数据质量告警与问题事件记录。
- `public.collector_watchlist`
  - 采集清单表。
  - 所有记录都会进入实时采集范围，不再按池分类。
  - `instrument_type` 标记采集类型，当前主要为 `stock` / `index`。
- `public.instruments`
  - 采集标的主数据。
  - 每天盘后由 `sync_instruments.py` 从 Tushare `stock_basic` 同步 active A 股主数据。
## 2. 采集读取表 / 写入表

### realtime_quotes

- 写入：
  - 当前盘中主写入口以 `sina` 为主，采集 cadence 为 `2s`。
  - 每天 `09:15`、`09:16`、`09:17` 各做一次源侧探测；只有探测到当天日期，才认定为交易日并进入盘中采集。
  - 正常连续采集窗口为 `09:29:58-11:30:02`、`13:00-14:57:02`。
  - `sina` 写入必须携带 source-side timestamp。
  - 当前写库依赖主键 `(instrument_id, quote_time)` 去重。
  - 数据库 CHECK 约束保证 `quote_time = trade_date + trade_time +08`，因此同一 source-side 时间的重复快照会被 `ON CONFLICT DO NOTHING` 丢弃。
  - 不再执行大表 `WHERE NOT EXISTS` 查重，也不再对重复快照做 `DO UPDATE`。
- 读取：
  - 独立聚合进程 `run_minute_aggregation_loop.py` 从 `realtime_quotes` 拉取快照；
  - 盘后真值由 `reconcile_daily` 直接以外部日线源写入 `kline_daily`；`aggregate_daily_kline()` 属于数据库遗留辅助函数，当前 collector 不把它当作主链路入口。

### kline_minute

- 写入：
  - `aggregate_1min_kline()` 写入 `period=1`；
  - `aggregate_5min_kline()` 从 `period=1` 生成 `period=5`；
  - `aggregate_15min_kline()` 从 `period=5` 生成 `period=15`；
  - `aggregate_30min_kline()` 从 `period=15` 生成 `period=30`；
  - `aggregate_60min_kline()` 从 `period=30` 生成 `period=60`。
- `source`：统一写入 `derived`。
- 运行口径：
  - collector 以固定顺序调用上述聚合函数，当前回看窗口分别为 `10 / 60 / 180 / 240 / 480` 分钟。
  - 由于 `kline_minute` 主键为 `(instrument_id, bar_time, period)`，重复运行以覆盖写为主，属于可重放链路。
  - `15/30/60` 分钟周期当前按交易时段对齐分桶：
    - 上午以 `09:30` 为起点
    - 下午以 `13:00` 为起点
    - 不再生成 `09:15 / 09:00 / 08:30` 这类非业务时间桶
- 约束：`realtime_quotes` 只写入秒级，`kline_minute` 为汇总事实，不保留历史分钟层以外的中间过渡表。
- 约束：当前保留窗口从 `2026-04-07` 起；`realtime_quotes` / `kline_minute` 以前的数据已清理。

### kline_daily

- 写入：
  - 盘后校准任务以 `trade_date` 为键写入/更新到当前 hypertable；
  - 若 `ON CONFLICT` 冲突，需明确以“是否幂等”作为重跑策略前提。
- 校验：
  - 当前历史日线已恢复回灌，范围覆盖到 `2010-01-28`；
  - 新的日线保留窗口目标已收敛为 `>= 2020-01-01`，但在 `bs` 完成实际裁剪并核验前，当前事实仍保持现有范围；
  - 仅可在既有主键内覆盖当日记录，不得删除或截断历史范围。

### daily_basic

- 写入：
  - `collector/sync_daily_basic.py` 按 `trade_date` 或日期区间从 `Tushare daily_basic` 拉取并写入 `public.daily_basic`
  - 当 `reconcile_daily --source tushare` 执行时，也会同步同日 `daily_basic`
- 当前已验证的历史范围：
  - `2020-01-02` 到 `2026-04-08`
- 主键：
  - `(instrument_id, trade_date)`
- 单位：
  - `turnover_rate`：`%`
  - `total_share / float_share / free_share`：`万股`
  - `total_market_cap / circulating_market_cap`：`万元`
- 约束：
  - `daily_basic` 与 `kline_daily` 同键对齐
  - 不再继续往 `kline_daily` 混塞基础指标

## 3. 日线校准链路

- 盘后主任务名：`reconcile_daily`。
- 现象层面观察：`data_quality_log` 已出现 `daily_reconcile/source_error`，多条为 `AKShare stock_zh_a_hist request failed`。
- 校准边界：
  - 以交易日为单位进行重跑/补齐。
  - 当前 `kline_daily` 历史已恢复，不再处于“仅单日保留”状态。
  - 关联输出：可在 `job_runs` 中追踪执行 `status/processed_count/error_message`。

## 4. 作业日志与数据质量日志

### job_runs

- 用途：记录任务生命周期（`job_name`, `job_type`, `status`, `started_at`, `finished_at`, `processed_count`）。
- 保留策略：只保留最近 `7` 天数据，超过窗口的数据由 `cleanup_data_quality_log.py --target all` 清理。
- 读取入口：`job_name='collect_realtime'`、`job_name='reconcile_daily'`、`job_name='sync_eastmoney_sectors'`、`job_name='sync_eastmoney_sector_stocks'` 为核心。

### data_quality_log

- 用途：记录数据异常（issue_type/issue_level）和源头（data_domain / ref_key）。
- 保留策略：只保留最近 `7` 天数据，超过窗口的数据由 `cleanup_data_quality_log.py --target all` 清理。
- 典型 issue_type：`source_error`。
- 盘中循环采集会补充 `loop_error` / `stale_snapshot` / `empty_payload` 等质量记录。
- `run_realtime_loop` 会把 `empty_payload` / `stale_snapshot` 视为软失败，只做退避，不计入主备切换；`empty_watchlist` 只提示配置或样本问题。
- 只有真实源故障或运行异常才会推动 failover 计数。
- 板块同步会补充 `sector_sync` / `sector_members` 域下的 `source_error`、`empty_member_frame` 或 `suspect_partial_member_frame`。
- 查询建议：按 `(data_domain, created_at)` 与 `issue_level` 过滤，区分盘后与盘中问题。
