# 数据采集运行

## collect_realtime

目标：盘中按最小延迟持续写入 `public.realtime_quotes`。

- 推荐命令：
  - `python collector/collect_realtime.py --host 127.0.0.1 --port 5432 --user wt --password '***' --dbname stock_realtime`

- 入口参数：
  - 交易品种来源：`collector_watchlist`。
  - 数据源可用性（AKShare/备用源）。
  - 采集频率与批次大小。

- 数据落库口径：
  - 写入目标：`public.realtime_quotes`。
  - 关键字段：`instrument_id`, `quote_time`, `current`, `volume`, `amount`, `trade_date`, `trade_time`, `is_closing`。
  - 当前实现中 `volume/amount` 写累计值，`delta_volume/delta_amount` 写本次增量。
  - `realtime_quotes` 当前只接收 source-side 时间落在 `09:29:56-11:30:03`、`12:59:58-15:00:03` 的记录；`09:25` 集合竞价最终点不再写入主链路。

- 成功判定（建议）：
  - 采样窗口内有新记录写入。
  - `quote_time` 时序连续，无明显时区/回退。

## run_realtime_loop

职责：维护 `collect_realtime` 的周期执行和失联重试。

- 推荐命令：
  - `python collector/run_realtime_loop.py --host 127.0.0.1 --port 5432 --user wt --password '***' --dbname stock_realtime --source sina --preferred-source sina --interval-seconds 2 --continue-on-error`

- 周期建议：当前主配置使用 `2` 秒；若需降压可回退到 `3` 秒，但对 3 秒级源更新会增加轮空概率。
- 当前盘中节拍：上一轮结束后立即进入下一轮，不再等待额外的 `2s` 节拍。
- 交易时段门控（默认开启）：
  - 仅在工作日 `09:29:56-11:30:03`、`12:59:58-15:00:03` 执行正常实时采集
  - 非交易时段进入静默轮询，不触发 heartbeat
  - 非交易时段当前按 `1s` 固定轮询
  - 交易时段内 heartbeat 仅按 `2s` 节流写入
- 失败处理：
  - `run_realtime_loop` 现在会读取 `collector/runtime/source_failover_state.json`
  - `empty_watchlist` 仍只提示配置/样本问题，不触发切源
  - `empty_payload`、`stale_snapshot` 会被当作软失败，只做退避，不再累计 failover 计数
  - 只有真实源故障或运行异常才会累计 failover 计数并触发切源
  - 连续真实失败达到阈值后会自动切换主源，当前仅在 `eastmoney` 与 `sina` 间做退避
  - 切到备源后会按固定周期探测首选主源，连续探测成功达到阈值后自动回切
  - 失败与软失败都会写入 `data_quality_log`
  - 状态会保留最近一次成功批次、主源与退避计数
  - 当前 collector 已增加分段耗时埋点：
    - `fetch_watchlist_seconds`
    - `latest_state_seconds`
    - `fetch_source_seconds`
    - `normalize_seconds`
    - `upsert_realtime_quotes_seconds`
    - `aggregate_1m_seconds`
    - `aggregate_multi_period_seconds`
    - `total_seconds`
  - 当单轮总耗时 `>= 5s` 时，会额外写一条 `realtime_collect/slow_cycle`
- 保护策略：采集写入时使用 `instrument_id + quote_time` 主键作为最终去重约束；由于 `quote_time` 必须等于 source-side `trade_date + trade_time +08`，同一代码、日期、时间重复到达会被主键冲突丢弃，不做更新也不重复插入。
- 当前写库 SQL 已简化为依赖 `realtime_quotes` 主键 `(instrument_id, quote_time)`：
  - `quote_time` 由 source-side `trade_date + trade_time` 生成
  - 数据库 CHECK 约束保证 `quote_time = trade_date + trade_time +08`
  - 重复快照通过 `ON CONFLICT (instrument_id, quote_time) DO NOTHING` 丢弃
  - 不再执行大表 `WHERE NOT EXISTS` 查重，也不再对重复快照做 `DO UPDATE`

## run_minute_aggregation_loop

职责：独立从 `public.realtime_quotes` 聚合 `public.kline_minute`，与秒级写库主链路分离。

- `1m`
  - 每分钟一次
- `5m`
  - 每 `5` 分钟一次
- `15m`
  - 每 `15` 分钟一次
- `30m`
  - 每 `30` 分钟一次
- `60m`
  - 每 `60` 分钟一次

## source_probe

职责：检测上游采集源状态并形成质量指标。

- 推荐命令：
  - `python collector/source_probe.py --host 127.0.0.1 --port 5432 --user wt --password '***' --dbname stock_realtime`

- 目标指标：
  - 连续失败次数
  - 成功/失败响应码
  - 每批次采集耗时
  - 源退化后是否已切换
- 当前输出语义：
  - `success`：实时与日线探测都成功
  - `partial`：实时或日线只成功其一
  - `error`：实时与日线都失败
- 异常上报：
  - `data_domain='collector_probe'`
  - `issue_type='realtime_source_error' / 'daily_source_error'`
  - `issue_level='warn'/'error'`

## cleanup_realtime_quotes

职责：清理 `public.realtime_quotes` 的历史秒级快照，只保留最近 `10` 个实际采集交易日。

- 推荐 dry-run：
  - `python collector/cleanup_realtime_quotes.py --host 127.0.0.1 --port 5432 --user wt --password '***' --dbname stock_realtime --retention-trading-days 10 --dry-run`
- 推荐正式执行：
  - `python collector/cleanup_realtime_quotes.py --host 127.0.0.1 --port 5432 --user wt --password '***' --dbname stock_realtime --retention-trading-days 10 --batch-size 50000 --vacuum`
- 交易日口径：
  - 以 `realtime_quotes.trade_date` 中实际存在数据的日期为准
  - 不读取交易日历，不读取 Tushare
- 影响范围：
  - 只清理 `realtime_quotes`
  - 不清理 `kline_minute`、`kline_daily`、`daily_indicator`

## cleanup_kline_minute

职责：清理 `public.kline_minute` 的历史分钟线。1 分钟线只保留最近 `45` 个实际采集交易日，5/15/30/60 分钟线只保留最近 `120` 个实际采集交易日。

- 推荐 dry-run：
  - `python collector/cleanup_kline_minute.py --host 127.0.0.1 --port 5432 --user wt --password '***' --dbname stock_realtime --one-minute-trading-days 45 --multi-period-trading-days 120 --dry-run`
- 推荐正式执行：
  - `python collector/cleanup_kline_minute.py --host 127.0.0.1 --port 5432 --user wt --password '***' --dbname stock_realtime --one-minute-trading-days 45 --multi-period-trading-days 120 --batch-size 50000 --vacuum`
- 交易日口径：
  - 以 `kline_minute.trade_date` 中实际存在数据的日期为准
  - 不读取交易日历，不读取 Tushare
- 影响范围：
  - 只清理 `kline_minute`
  - 不清理 `kline_daily`、`daily_basic`、`daily_indicator`、`daily_adj_factor`

## 运行态说明

- `collect_realtime.py` 仍是单次采集入口，只负责抓取并写入 `public.realtime_quotes`。
- 当前盘中主源为 `sina`；`eastmoney` 不再作为盘中主写入口。
- `run_realtime_loop.py` 是推荐的盘中常驻入口，负责循环调度、退避和源切换。
- `run_minute_aggregation_loop.py` 是当前分钟线独立聚合入口，负责从 `public.realtime_quotes` 生成 `public.kline_minute`。
- `collector/runtime_control.py` 管理运行态 JSON，避免在多个脚本里各自维护源状态。

## 与 `kline_minute` 聚合衔接

当前分钟聚合由独立常驻进程调用数据库聚合函数形成分钟及其派生周期：

- `aggregate_1min_kline()`：`realtime_quotes -> kline_minute(period=1)`
- `aggregate_5min_kline()`：`kline_minute(period=1) -> period=5`
- `aggregate_15min_kline()`：`kline_minute(period=5) -> period=15`
- `aggregate_30min_kline()`：`kline_minute(period=15) -> period=30`
- `aggregate_60min_kline()`：`kline_minute(period=30) -> period=60`

当前 `15/30/60` 分钟周期的分桶口径：
- 上午以 `09:30` 为起点
- 下午以 `13:00` 为起点
- 不再生成 `09:15 / 09:00 / 08:30` 这类非业务时间桶
